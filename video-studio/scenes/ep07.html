§11 · The Problem

Every wallet in existence rests on the same fragile object

Fig. 1 — A twelve-to-twenty-four word sequence. Written on paper, it is the whole wallet: the key, the backup, and the single point of failure at once.
Lose it
The wallet is gone forever.
Let it be photographed
The wallet belongs to someone else.
No recovery · no appeal · no support
Responsible for more permanent loss than any exploit in the industry's history.
Living Identity replaces it with
What you know
security questions
Where you are
registered locations
Two things you cannot misplace.
§11 · Registration

Three independent layers

Layer 01
3–5 security questions
Answers only the owner would know. Sixty percent correct is required to proceed.
Layer 02
Up to 3 GPS locations
Home, workplace — anywhere the owner reliably returns to.
Layer 03
6–8 digit recovery PIN
A fallback for when GPS is unavailable. PBKDF2, 100,000 rounds.
Each layer is stored independently, as a one-way hash. Never as plaintext, in any layer, at any point.
Fig. 2 — Three factors, stored separately. Compromising one reveals nothing about the others.

§11 · Recovery Sequence

Five stages, each with its own gate

01
Answer the security questions
At least 60% correct — partial memory is enough, exact recall is not required.
02
Prove location — or enter the PIN
GPS grid match, or a 6–8 digit PIN hashed with PBKDF2 at 100,000 rounds.
03
Rate limiting
Five failed attempts trigger a five-minute lockout. A self-test mode rehearses the whole flow without touching those counters.
04
48-hour time-lock
Specified in the design and being brought on chain — the original owner can cancel the recovery during this window.
05
Control transfers
Only after the window closes uncontested.
The theft protection
An attacker who somehow satisfies every factor still cannot complete the transfer silently.
Fig. 4 — The time-lock converts a silent theft into a visible one, which is the only kind the owner can act on.
